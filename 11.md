Admin Job Configuration Page — Technical Design

Owner: Boyi ZhaoReviewer: JianRepositories: recruitdirect-web, webservice

1. Objective

Add an admin-only page that allows an administrator to:

Enter a Job ID

Load the corresponding job information

View and edit:

Resume process limit

Interview limit

Resume process model

Interview model

Save the updated configuration to the database

Development will start after this design is approved.

2. Frontend Design

New Page

Create:

src/views/admin/JobConfiguration.vue

The page will contain:

Job ID input

Load button

Read-only job summary

Four editable configuration fields

Save button

Loading, success, and error states

Sidebar

Modify:

src/layouts/full/vertical-sidebar/sidebarItem.ts

Add a new menu item:

{
  title: 'Job Configuration',
  icon: IconSettings,
  to: '/admin/job-configuration',
  requiresAdmin: true
}

The existing sidebar logic already hides requiresAdmin items from non-admin users.

Route

Modify:

src/router/MainRoutes.ts
src/router/index.ts

Add route:

/admin/job-configuration

The route will include meta.requiresAdmin = true.

The global route guard will verify:

usersStore.userData?.role === 'admin'

Non-admin users will be redirected to the Job List page.

API Calls

Modify:

src/stores/jobList.ts

Add two methods:

fetchAdminJobConfiguration(jobId)
updateAdminJobConfiguration(jobId, configuration)

The existing Axios interceptor will automatically attach the Firebase token.

3. Backend Design

Use the existing backend flow:

JobController
→ JobService
→ JobRepository
→ Job entity

API 1: Load Configuration

GET /job/admin/configuration/{jobId}

Response:

{
  "jobId": "job-uuid",
  "title": "Software Engineer",
  "companyName": "Example Company",
  "resumeProcessLimit": 50,
  "interviewLimit": 20,
  "resumeProcessModel": "model-name",
  "interviewModel": "model-name"
}

API 2: Update Configuration

PUT /job/admin/configuration/{jobId}
Content-Type: application/json

Request body:

{
  "resumeProcessLimit": 50,
  "interviewLimit": 20,
  "resumeProcessModel": "model-name",
  "interviewModel": "model-name"
}

Authorization

Both endpoints will use:

@RequireAuth

After Firebase authentication, the backend will check:

hiringClient.getRole() == HiringClient.Role.admin

A non-admin user will receive:

403 Forbidden

The backend will not trust the role stored in frontend local storage.

4. Database Design

Recommended approach: add four nullable columns to the existing job table.

ALTER TABLE job
    ADD COLUMN resume_process_limit INT NULL,
    ADD COLUMN interview_limit INT NULL,
    ADD COLUMN resume_process_model VARCHAR(128) NULL,
    ADD COLUMN interview_model VARCHAR(128) NULL;

Modify:

recruitdirect-domain/.../model/entity/Job.java

Add the corresponding entity fields.

A separate configuration table is not necessary because the configuration has a one-to-one relationship with a Job.

6. Validation

Backend validation:

Job ID must exist

Limits must be positive integers when provided

Model names must not exceed 128 characters

Empty model names will be stored as NULL

Non-admin users cannot read or update configuration

Expected responses:

200 — Success
400 — Invalid input
401 — Missing or invalid token
403 — User is not admin
404 — Job not found
500 — Server error
